## Plan: render — occlusion-aware light-volume boundary seed (clamped seed inside a wall pops off)

- **Issue:** #2330
- **Model:** opus — the approach is ruled (architect triage 2026-07-28) and this plan pins every design call below; what remains is a bounded CPU change in one render prefab system plus its fixture, tests, and harness wiring. Not fable: no new shader stage, no algorithm design left open. Not sonnet: the relocation search has a correctness rule (face-only candidates) and a parity invariant an implementer must hold, and the change sits on the per-frame gather.
- **Date:** 2026-09-05
- **Planner:** fable worker, pool-1 (Windows host). Everything in "Verified current state" is source-verified against `origin/master` `53973faa`.

### Scope

Implement the architect's pick **(b) with (a) as the in-policy fallback**: when an out-of-window light's per-axis-clamped seed cell is occluded (voxel bit OR light-blocker bit in the CPU mirror `BUILD_LIGHT_OCCLUSION_GRID` already maintains), relocate the seed to the nearest unoccluded cell on the window face(s) the clamp touched, at the corrected residual; when no such cell exists within the light's remaining reach, skip the light explicitly. In-window lights and free clamped cells keep today's code path byte-for-byte. Ship one positive-fire fixture (a new lighting demo target) whose DOMAIN-STATE line proves the relocation fires, wire it into `scripts/light-verify.py`, and unit-test the pure relocation logic against synthetic bitfields.

One task, one PR (`Closes #2330`). No stack: the fixture is the acceptance gate for the engine change, so splitting them would strand the gate.

### Verified current state (source-checked, with the confirmed repro mechanism)

- **The trap mechanism is exactly as the issue describes, and it is in the propagate shader's neighbor gate, not the seed pass.** `engine/render/src/shaders/c_propagate_light_volume.glsl:152-163` (Metal twin identical): a cell adopts a neighbor's residual only when that *neighbor* is not occluded (`voxelOcclusionGetBit || lightBlockerGetBit`). A seed written into an occluded cell S is therefore never read by any of S's six neighbors — S keeps its own alpha (the self candidate at `:132`) but the wavefront never leaves. `c_seed_light_volume.glsl:56-70` performs no occlusion test; it only range-checks the cell. So the seed-eligibility predicate that mirrors the gate is `occluded(cell) = voxelBit(cell) || blockerBit(cell)` — the propagate-gate parity invariant the architect asked the plan to carry.
- **The gather emits the clamped seed with no occlusion test** — `engine/prefabs/irreden/render/systems/system_compute_light_volume.hpp:291-332`: per-axis clamp (`:295-302`), residual early-out (`:303-309`), the `// Known residual (#2330 …)` comment at `:315-325` marking this exact site, then `toGpuLight(..., volumeOriginVoxel + clamped, origin, seedAlpha)`.
- **The CPU occupancy data exists, is current-frame, and is indexable from the gather.** `system_build_light_occlusion_grid.hpp:222-235` holds `voxelBitfield_` (filled in `tick`, `:256-279`), `blockerBitfield_` (filled in `endTick`, `:291-304`) and `origin_` (`:254`, from `frozenAwareCameraAnchorVoxel()` — the same helper `COMPUTE_LIGHT_VOLUME` calls at `:455`). `detail::gridInBounds` / `gridFlatIndex` / `gridSetBit` exist (`:95-118`); there is no read-side `gridGetBit`. `engine/system/CLAUDE.md:309,325,346`: systems execute in `registerPipeline` list order and the legacy list form is one-system-per-group, so `BUILD`'s `endTick` (blocker raster + SSBO upload) completes before `COMPUTE`'s first `tick`. **1. Read-side occupancy query in `system_build_light_occlusion_grid.hpp`.**
- `detail::gridGetBit(const std::vector<std::uint32_t> &bitfield, int wx, int wy, int wz, const ivec3 &origin) -> bool`: mirror of `gridSetBit` — `gridInBounds` false → `false` (the shader's out-of-range answer), else `(bitfield[flat >> 5] >> (flat & 31)) & 1`.
- `struct detail::LightOcclusionGridView { const std::vector<std::uint32_t> *voxel_ = nullptr; const std::vector<std::uint32_t> *blocker_ = nullptr; ivec3 origin_{}; bool valid() const; bool occluded(const ivec3 &world) const; }` — `occluded` is `gridGetBit(*voxel_, …, origin_) || gridGetBit(*blocker_, …, origin_)`, the OR the propagate gate applies at `:160-161`; `valid()` is both pointers non-null. This struct **is** the parity invariant in code: one predicate, two bitfields, indexed with the producer's origin.
- `System<BUILD_LIGHT_OCCLUSION_GRID>::occlusionView() const` returning `{&voxelBitfield_, &blockerBitfield_, origin_}`.
- `static_assert(kLightVolumeHalfExtent <= kMaxLightOcclusionGridSideVoxels / 2)` placed in `system_compute_light_volume.hpp` beside the existing `LightVolumeParams` drift asserts (`:360-367`, the one header that includes both).

**2. Relocation helper in `system_compute_light_volume.hpp` (`detail`, pure, unit-testable).**
`detail::relocateOccludedBoundarySeed(const LightOcclusionGridView &view, const ivec3 &volumeOrigin, const ivec3 &clamped, const bool clampedAxis[3], int maxDist, ivec3 &outClamped, int &outExtraDist) -> bool`.
- **Candidate set — face cells only.** A candidate `B` is a window cell (`B[i] ∈ [−H, H−1]` for all axes) with `B[a] == clamped[a]` for at least one clamped axis `a`, i.e. it lies on a window face the clamp touched. This is the correctness rule: for such `B` there is an L1-shortest path from the light's origin `O` that stays outside the window until `B` itself, and `manhattan(O, B) = manhattan(O, clamped) + manhattan(clamped, B)` (the #2310 per-axis argument extended to the face: the clamped axis is traversed last, the other clamped axes split exactly because `B` lies on the clamped side, unclamped axes are unchanged). An **interior** candidate (all clamped-axis coordinates strictly inside) would be seeded as if the straight-line path through the in-window wall were free — that is light-through-wall, strictly worse than the pop the issue documents as "benign — never light-through-wall". Face cells inherit only the approximation #2310 already makes (outside the window is treated as free), nothing new.
- **Deterministic nearest-first enumeration** (render-verify determinism depends on it; pure integer logic, host-independent): for `dist = 1 .. maxDist`, for each clamped axis `a` in index order x→y→z, let `(u, v)` be the other two axes in index order; for `du = −dist .. +dist`, `dv = −(dist − |du|)` then `+(dist − |du|)` (once when zero); candidate `= clamped` with `[u] += du`, `[v] += dv`; skip when out of window; return the first candidate with `!view.occluded(volumeOrigin + candidate)`, with `outExtraDist = dist`. Corner/edge clamps enumerate all their faces at each `dist` before moving to `dist + 1`, so "nearest" holds across faces. Ties resolve by that fixed order (lower axis, negative direction first) — stable frame-to-frame because the light and geometry are world-fixed, so a pan cannot flip the pick.
- **Search bound = remaining reach, not a magic radius.** `maxDist = reach − boundaryDist − 1` where `reach = outMaxRadius > 0 ? outMaxRadius : kLightVolumePropagateIterations` (the same denominator `stepFalloff` uses, `:266-268`). Any farther cell would seed at alpha ≤ 0 and be dropped by the propagate anyway, so this bound is the physics, and it caps cost at `≤ 31` rings ⇒ `≤ 2·31·32 ≈ 2k` bit tests per face (≤ 3 faces), only on frames where an out-of-window light's clamp is occluded. This is the "implementer sizes the radius" call from the triage comment, sized to the light's own residual budget instead of a constant.

### Gotchas

- **Index with the producer's origin, not the light volume's.** `LightOcclusionGridView::origin_` is `BUILD`'s `origin_`, exactly as the shader reads `occlusionWorldOrigin` from the SSBO header rather than `lightVolumeWorldOrigin`. The two agree every frame today (same helper, same pipeline order), and on the one frame `BUILD` skips (no matching canvas, `ranThisFrame_` false) the CPU mirror is stale in lockstep with the un-re-uploaded SSBO — parity holds either way. Using `volumeOrigin` for the bit index would silently break that on the stale frame.
- **The `blockerBitfield_` skip-clear optimisation is not a staleness bug.** When no blocker existed last frame the vector is not memset (`:300-303`) because it is already all-zero — a valid mirror. Do not "fix" it in this PR.
- **`SKIPPED` ordering is load-bearing for light-verify.** Residual-exhausted lights must keep reporting `SKIPPED` (checked before the occlusion test) so the "beyond" category assertion stays exact; only a clamp that is occluded *and* within reach reaches the relocation path.
- **Face-only candidates, never interior.** An interior pick is light-through-wall (see Approach step 2). The `NeverRelocatesIntoTheInterior` test is the lock; a reviewer should also read the enumeration for a stray "walk inward" branch.
- **Relocation is single-seed and asymmetric by design.** With the wall's end on one side nearer than the other, only that side's approach is lit (the far side is under-lit, never over-lit); a wall centred on the light's face coordinates picks the negative-direction end by the fixed order. This is the ruled policy ("seed the closest unoccluded cell"); seeding every free cell on the minimal ring is the follow-up lever if a demo ever reads the asymmetry as an artifact — it is not part of this task, and the 256-source cap is why.
- **The residual bound already caps cost** — do not add a second radius constant; two bounds that disagree is the kind of drift the exactness argument exists to prevent.
- **`hasSpot` must be set after the relocation block**, else a `SKIPPED_OCCLUDED` spot enables the consumer's winning-ID read for a light that never seeded (#2318 byte-identity for no-spot scenes).
- **light-verify's token regex is a whitelist** — widening it lands in the same commit as the enum; assertion 5 fails on a *missing* entry precisely so a future token addition cannot pass vacuously again.
- **Baseline path split.** Keep `DEFAULT_TARGET`'s baseline directory byte-for-byte where it is; only non-default targets get the `<target>/` component, or the committed macOS references move.
